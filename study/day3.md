## 3일차

- 회원 도메인과 리포지토리 생성
    - repository 패키지 - 회원 객체를 저장하는 저장소
    - 실무에선 공유되는 변수일 경우 hashmap 대신 concurrenthashmap 써야 함
    - map?
        - 키와 값을 하나의 쌍으로 저장, 요소의 저장 순서 유지 x
        - hashmap: hash 알고리즘을 사용하여 검색 속도가 빠르다
- test case 작성***
    - junit이라는 프레임워크를 이용
    - 순서
        - 도메인을 끌어와서 set을 해줌
        - repository에 save를 해줌
        - 메서드에 맞게 assertThat과 같은 메서드로 원하는 값이 나오는지 확인 (null을 넣으면 에러 출력)
    - 순서에 의존적으로 설계를 하면 안된다
    - **@AfterEach** 테스트가 하나 끝나고 나면 데이터가 클리어 되어야 한다
        - repository에 clear 메서드를 선언, 하나의 테스트가 끝날 때마다 저장소에 있는 것을 지워서 순서 상관 없이 실행되어도 오류가 나지 않게 방지
    - 테스트 케이스를 먼저 작성하는 것: 테스트 주도 개발(tdd)
- 서비스 개발
    - 서비스는 비즈니스 의존적 설계, naming
    - repository는 개발적으로 단어 선택을 한다
    - 메서드 분리는 ctrl + shift + m
- 서비스 테스트
    - class 명 잡고 ctrl + shift + t를 누르면 자동으로 테스트 클래스틀이 생성이 된다
    - 한글로 메서드명 지어도 됨
    - given: 주어진 것
    - when: 실행한 것
    - then: 원하는 결과값
    - command alt v = 변수 추출
    - shift f10 = 전에 실행했던거 고대로 실행해줌
